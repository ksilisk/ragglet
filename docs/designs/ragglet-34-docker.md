# ragglet-34 — Docker-окружение стенда

Рецензент с чистой копией репозитория запускает `./ragglet start --docker --open`.
Лаунчер собирает образ, поднимает Ragglet, Qdrant и Redis, ждёт доступности API
и открывает UI. На машине нужны Git, Python 3.9+ для лаунчера и Docker с Compose.
На macOS требуется Docker Desktop 4.34+ с включённой опцией **Enable host networking**.
Первая сборка и первая загрузка модели требуют интернета.

## От запуска до результата

1. На пустом стенде UI подсказывает собрать индекс по профилю `demo`.
   Корпус уже лежит в `datasets/demo`. Сборка загружает модель и создаёт индекс.
2. Пользователь открывает сценарий `baseline_qdrant`, запускает его и смотрит результат.
   Те же действия доступны в CLI через `./ragglet build demo` и
   `./ragglet run baseline_qdrant`. Для демо ключи провайдеров не требуются.
3. `./ragglet status` показывает, где работает сервер, состояние сервисов и задачи.
   `./ragglet stop` останавливает сервер. `./ragglet stop --services` также останавливает
   локальные зависимости, которые обслуживает этот стенд. При активных или ожидающих
   задачах действуют те же правила подтверждения, что при нативном запуске.
   Артефакты, индексы и кэш доступны при следующем запуске.

## Ответственность лаунчера и Compose

`start` по умолчанию запускает сервер на хосте (в частности, для замеров на Mac с MPS).
`start --docker` запускает сервер в контейнере на CPU. Лаунчер сам передаёт Git SHA
текущей сборки и сохраняет достаточно информации для остановки своего сервера.
Повтор команды для работающего стенда возвращает его адрес. При запуске на Linux
контейнер должен писать в каталоги клона с правами пользователя, в том числе при UID,
отличном от 1000. Для начала работы не требуется ручная смена владельца файлов.

Стандартный Compose-стенд содержит один Qdrant и Redis. Профиль Compose выбирать в CLI
не требуется. Пользовательские сценарии и профили индекса задают адреса явно. Для S5
есть отдельный пример с двумя независимыми Qdrant, профилем индекса `demo_sharded`
и сценарием `s5_distributed_like`. В этом примере список адресов для страницы стенда
должен включать оба сервиса.

## Сеть и данные

Только сервер Ragglet использует `network_mode: host`. Он слушает loopback.
Qdrant и Redis публикуют порты на `127.0.0.1` (6333 и 6379, второй Qdrant — 6334).
Это позволяет использовать адреса `localhost` из существующих YAML и snapshot
на хосте и в контейнере без подмены URL. Если Docker Desktop не передаёт соединения
между Mac и контейнером, лаунчер должен объяснить, где включить host networking.

- `configs/` и `results/` монтируются на запись. Правки из UI и результаты доступны в клоне.
- `datasets/` монтируется на чтение. Модели и HF-датасеты кешируются между запусками.
- Штатная остановка сохраняет тома Qdrant и Redis.
- В один момент времени у стенда один сервер. Нативные и контейнерные замеры задержек
  отражают разные среды исполнения.

## Образ и проверка

Многостадийная сборка собирает UI с Node и устанавливает сервер с Python 3.12.
Контейнер использует CPU-сборку torch и работает без root. Версия исходников сборки
попадает в manifest прогона. В контекст сборки включаются только необходимые файлы.

Приёмка включает сборку образа, запуск CLI, проверку UI и API, сборку демо-индекса,
прогон с сохранением артефактов, перезапуск с сохранением данных и оба варианта
остановки. Проверка S5 использует отдельные коллекции или временные тома. Проверяем
запись при нестандартном Linux UID и доступ к loopback из macOS при включённой опции
Docker Desktop. Тестовый запуск не должен перезаписывать рабочие коллекции.
