# ragglet-25 — [Э3/C2] Улучшение merge и дедупликации

Задача требует настраиваемых методов слияния, тестов ранжирования и сравнения
качества на одиночном, гибридном и распределённом retrieval. Этот документ
фиксирует согласованный объём реализации; исходный анализ выполнен на `4793017`.

## Что требуется и что обнаружено

| Основание | Содержание |
|---|---|
| Требование задачи | Проанализировать RRF, weighted sum, interleave, нормализацию, веса и дедупликацию; проверить качество и обосновать выбор метода. |
| Найдено в коде | Настройки нормализации и weighted interleave не доходят из сценария до функций. Квоты скрытого weighted interleave могут недозаполнять результат. |
| Найдено в коде | Локальные повторы чанка дают несколько вкладов. `deduplicate: false` не меняет RRF/weighted sum. RRF возвращает raw score представителя, weighted sum записывает fused score в то же поле. |
| Гипотеза | RRF и min-max по отдельным шардам могут ухудшать глобальное ранжирование. Это свойство выбранного метода, а не доказательство ошибки или причины деградации S5. |

Пример: источник A возвращает `a=0.90, b=0.89`, B — `c=0.20, d=0.10`.
При сопоставимых шкалах глобальный порядок — `a,b,c,d`, но RRF с равными весами
даёт `a,c,b,d`: сравниваются локальные ранги. Для vector + BM25 исходные scores
обычно несопоставимы, поэтому универсально заменить RRF суммой нельзя.

## Обязательные изменения

### Настройки

```yaml
retrieval:
  strategy: fanout_merge
  merge:
    method: weighted_sum
    normalize: minmax
    rrf_k: 60
    interleave_weighted: false
    deduplicate: true
```

Это фрагмент: источники и остальные секции задаются обычным способом.
`normalize: minmax | none` действует для weighted sum; `interleave_weighted`
включает учёт существующих `sources[].weight` в interleave. RRF остаётся default.
Поля доступны через YAML, API/meta и редактор; входят в snapshot и ключ кэша.
Веса конечны и неотрицательны, у fanout есть хотя бы один положительный вес,
`rrf_k >= 1`. Вес 0 исключает вклад в merge, но не сетевой вызов и его измерение.
`single` сохраняет прежний путь без merge.

### Алгоритмы и дедупликация

- **Общий вход.** Порядок источников задаёт конфигурация, внутри выдачи сохраняется
  порядок backend. Scores конечны, chunk/doc IDs непустые. Повторы `chunk_id`
  внутри одного источника удаляются до нормализации, ранги пересчитываются с 1.
  Разные `doc_id` для одного чанка — ошибка данных. Разные чанки документа остаются.
- **RRF.** `sum(weight / (rrf_k + rank))`, по одному вкладу каждого источника.
- **Weighted sum.** `sum(weight * normalized_score)`, отсутствие кандидата даёт 0.
  `none` сохраняет исходный score; min-max — `(x-min)/(max-min)`, а при диапазоне
  `<= 1e-9` даёт 0 всему списку, включая singleton. Пустые списки не участвуют.
  Отрицательные scores разрешены; переполнение отклоняется. Это нормализация
  внутри top-k, не вероятность релевантности.
- **Interleave.** Обычный round-robin сохраняется. Взвешенный режим использует
  smooth weighted round-robin: на каждом шаге прибавить веса доступных источников,
  выбрать максимальный счётчик, вычесть из него сумму доступных весов. При равенстве
  выбирается первый источник конфигурации. Дубли пропускаются до выбора, пустые
  источники исключаются; выдача заполняется до `top_k`, пока есть кандидаты.
  Для весов 2:1 и длинных непересекающихся списков порядок — `A,B,A,A,B,A`.
- **Межисточниковые повторы.** RRF/weighted sum всегда объединяют вклады по чанку.
  Для совместимости `deduplicate: false` принимается, но preflight предупреждает,
  что флаг действует только на interleave. У interleave `false` разрешает повтор
  чанка из разных источников; локальные повторы всё равно удаляются.

Для RRF/weighted sum при равном fused score порядок определяется лучшим локальным
рангом, индексом соответствующего источника, затем `chunk_id`. Представитель
выбирается по лучшему локальному рангу и индексу источника, без сравнения raw
scores разных шкал. Нулевые веса не участвуют ни в выборе, ни в накоплении.

Weighted sum поддерживает scores с направлением «больше — лучше». Preflight
проверяет метрику используемых коллекций и отклоняет Euclid/неизвестную метрику
для этого метода: нормализация не исправляет обратное направление расстояния.
RRF/interleave работают по готовому порядку и не требуют такого ограничения.

### Контракт scores

Добавляется необязательное `score_fused`; `score_raw` всегда сохраняет оценку
представителя. У RRF/weighted sum fused содержит результат формулы. У single
и interleave fused отсутствует: искусственный `1/rank` не вводится.

Context и noop rerank используют fused, если он задан (включая 0), иначе raw.
Настоящий reranker выдаёт собственную оценку. Для threshold/adaptive context
после RRF меняется шкала: пороги необходимо пересмотреть. Interleave не создаёт
сопоставимых scores; при таком context без настоящего reranker preflight выдаёт
предупреждение об использовании raw scores. Выбор по рангу остаётся корректным.
Метрики качества продолжают использовать порядок и qrels.

Новые debug-колонки и форматы артефактов не добавляются. Кэш хранит новый score
в объекте результата; cache hit эквивалентен miss по выдаче. Таймеры и политика
ошибок retrieval сохраняются.

## Проверка и сравнение качества

1. Табличные тесты формул, весов, равенств, локальных/межисточниковых повторов,
   singleton/константных/пустых списков, отрицательных scores и неверных параметров.
   Отдельно — заполнение interleave, нулевые веса и неизменность входных объектов.
2. Проверка через `retrieve_items`: single, один/несколько vector-источников,
   vector + keyword, последовательный/async fanout, новые настройки и score.
   Регрессия context/noop/cache, preflight, meta и редактора; полный набор проверок.
3. Небольшой воспроизводимый экспериментальный скрипт использует публичный корпус
   с qrels и одни и те же кандидаты для всех merge. Сравнивает single, гибридный
   поиск и разбиение одного векторного индекса на два непересекающихся шарда.
   Фиксирует датасет, модель, seed, глубину кандидатов, параметры и число запросов.
   Для отделения merge от ANN допускается точный локальный векторный поиск;
   такой результат явно не называется замером распределённого Qdrant или S5.
4. Отчёт показывает nDCG@10, recall@10, MRR@10 и число уникальных результатов.
   Веса 1:1, 2:1, 1:2 и обе нормализации сравниваются как заранее заданные варианты,
   без заявления о подобранном оптимуме. Synthetic/demo служит проверкой механики;
   выводы о качестве требуют публичного датасета с qrels. Если реальные прогоны
   S5 недоступны, это остаётся явным ограничением, без обещания устранить деградацию.

## Наши решения и границы

Имена новых полей, разделение raw/fused, алгоритм weighted interleave и правила
пограничных случаев — решения этой реализации, а не дословные требования карточки.
Общий default остаётся RRF; рекомендации зависят от результатов сравнения.

За границами: искусственные scores interleave, большая система захвата/replay,
новые debug-артефакты, автоматический подбор весов, новые сервисы, кластеризация,
изменение timeout/fallback и дедупликация похожих текстов или целых документов.

Изменения идут в том же PR: отдельный коммит уточнения дизайна, затем реализация
с тестами и воспроизводимым сравнением. Публичные материалы содержат только ключ
и название задачи, общие настройки и результаты без внутренних адресов.
