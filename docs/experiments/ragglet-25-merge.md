# ragglet-25 — сравнение методов merge

На этом корпусе RRF подходит для vector + BM25, а сумма без нормализации
с равными весами сохраняет качество одиночного поиска при разбиении одного
векторного индекса на шарды. Общий default остаётся RRF. Это сравнение методов
на фиксированных кандидатах; оно не устанавливает причину деградации S5.

## Условия

- [NFCorpus](https://huggingface.co/datasets/BeIR/nfcorpus), test: 323 запроса,
  3633 документа; title + text, один документ = один чанк.
- [all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2),
  нормализованные embeddings, максимум 256 токенов. Точный cosine, CPU float32.
- BM25 из ragglet: `k1=1.2`, `b=0.75`. Два логических шарда: случайное
  непересекающееся разбиение корпуса на 1817 и 1816 документов, seed 42.
- По 30 кандидатов от каждого источника, merge до 30, метрики по документам @10.
  Одни и те же кандидаты используются всеми методами. Reranker отключён.
- Заранее заданная сетка: веса 1:1, 2:1, 1:2; RRF k=10/60/100; sum minmax/none;
  interleave обычный и взвешенный. В гибриде первый вес — vector, второй — BM25.
  Всего 43 варианта с baseline и проверками одного источника; подбора по qrels нет.

## Результаты

В таблице равные веса, RRF k=60. Полная сетка, точные значения, revisions и хеши
данных находятся в [summary JSON](ragglet-25-summary.json).

| Retrieval | Merge | nDCG@10 | Recall@10 | MRR@10 |
|---|---|---:|---:|---:|
| Один vector | — | 0.3167 | 0.1550 | 0.5077 |
| Один BM25 | — | 0.3062 | 0.1486 | 0.5138 |
| Vector + BM25 | RRF | 0.3425 | 0.1717 | 0.5501 |
| Vector + BM25 | Sum, minmax | 0.3360 | 0.1610 | 0.5404 |
| Vector + BM25 | Sum, none | 0.3230 | 0.1633 | 0.5246 |
| Vector + BM25 | Interleave | 0.3273 | 0.1692 | 0.5221 |
| Два vector-шарда | RRF / interleave | 0.2975 | 0.1539 | 0.4684 |
| Два vector-шарда | Sum, minmax | 0.2960 | 0.1529 | 0.4661 |
| Два vector-шарда | Sum, none | 0.3167 | 0.1550 | 0.5077 |

Все merge возвращают 30 уникальных документов; отдельный BM25 — в среднем 22.30.
Fanout с одним источником сохраняет метрики одиночного vector для всех методов.
Сумма raw scores двух шардов воспроизводит последовательность scores одиночного
поиска для 323/323 запросов, порядок IDs — для 293/323: при равных scores
отличается правило разрешения равенств. Метрики @10 совпали.

В гибриде RRF k=10/60/100 с равными весами дал nDCG 0.3430/0.3425/0.3427;
основания менять default k=60 по этому опыту нет. Веса 2:1 и 1:2 у RRF k=60
дали 0.3301 и 0.3391. Weighted interleave 2:1 повысил recall до 0.1737,
но nDCG составил 0.3326. Неравные веса ухудшили nDCG на однородных шардах.

## Как воспроизвести

Из корня репозитория, с Python 3.12 и CPU-зависимостями на Linux:

```bash
uv run --frozen --no-default-groups --extra docker-cpu python scripts/compare_merge.py \
  --revision b5026a0e96e8a7ac4f95f482a596389289d46269+a451b3b26d3ae1358f259c1a3a4dd61fcea35a65 \
  --model-revision 1110a243fdf4706b3f48f1d95db1a4f5529b4d41 \
  --output results/merge-comparison.json
```

Первый запуск загружает публичные данные и модель. JSON содержит также метрики
каждого запроса. Повторный запуск с закреплёнными revisions воспроизвёл все
значения первого. Скрипт дополнительно проверяет на реальных кандидатах, что
локальный повтор чанка не меняет результат RRF и weighted sum.

## Ограничения

Один датасет, одна модель, одна глубина кандидатов; статистическая значимость
различий не оценивалась. Это локальный точный поиск на логических шардах,
без ANN, сетевых запросов, измерений задержки и прогона S5. Рекомендация
`weighted_sum + normalize: none` относится к сопоставимым scores одной модели
и метрики на непересекающихся шардах с равными весами. Для конкретного стенда
её следует проверить на его qrels и кандидатах.

Исправления локальных дублей и заполнения interleave проверяются отдельно
тестами. Рост качества гибридного поиска в таблице — эффект сочетания источников
и выбранного метода, а не измерение выигрыша этих исправлений.
